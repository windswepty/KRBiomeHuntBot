# 🏹 한바헌봇 (KRBiomeHuntBot)

디스코드 서버를 위한 **포인트 이코노미 & 포상 시스템 디스코드 봇**입니다.
유저들의 서버 활동(채팅, 출석, 희귀 바이옴 제보 등)으로 포인트를 적립하고,
포인트 상점과 럭키 뽑기에서 상품 · 역할을 획득할 수 있습니다.

---

## ✨ 주요 기능

### 1. 📅 일일 출석체크 (`/출석`, `/출석설정`)

하루 한 번 출석하면 포인트를 받고, **연속으로 나올수록 더 받습니다.**

매일 조금씩 얹는 방식이 아니라 **주기를 채운 날에 한 번 크게** 줍니다.
'일주일을 채웠다'는 감각이 분명하고, 며칠째인지 세지 않아도 목표가 눈에 보입니다.

```
 1~6일    100 P
 7일      200 P  (+100)   🔥 1주차
 8~13일   100 P
14일      300 P  (+200)   🔥 2주차
21일      400 P  (+300)   🔥 3주차
```

| 설정값 | 뜻 |
| :--- | :--- |
| `base` | 매일 기본 지급량 |
| `cycle` | 며칠마다 추가 보상 (0이면 사용 안 함) |
| `cycle_step` | 주기당 증가폭 — 1주차 +100, 2주차 +200 … |
| `cycle_max` | 추가 보상 상한 (0이면 무제한) |
| `milestones` | 특정 일수 특별 보상 (선택) |

- `/출석설정` 에서 저장하면 **며칠차에 얼마가 되는지 즉시 계산**해서 보여줍니다.
  숫자만 바꿔놓고 결과를 모르면 조정할 수가 없기 때문입니다.
- 하루라도 거르면 연속은 **1일로 초기화**됩니다.
- 한국 시간 **매일 밤 12시** 기준으로 리셋됩니다.

> ⚠️ 무제한(`cycle_max = 0`)이면 1년 연속 시 52주차에 `+5,200 P` 가 나갑니다.
> 상한을 둘지는 운영진이 정합니다.

> ℹ️ 기존 유저는 과거 출석 기록이 날짜 하나뿐이라 **연속일수를 복원할 수 없습니다.**
> 도입 시점부터 1일로 시작합니다.

### 2. 💬 채팅 활동 자동 적립 (명령어 없음 · 자동 동작)
- 서버 텍스트 채널에서 메시지 **10회**마다 **+10 포인트** 자동 적립 (일일 상한 없음)
- **스팸 방지 필터링**
  - 사진 / 첨부파일 / 스티커 메시지 제외
  - GIF 링크(Tenor, Giphy, Gfycat, `.gif`, `.gifv`) 제외
  - URL · 커스텀 이모지 · 유니코드 이모지를 제거한 뒤 **내용이 남지 않으면 카운트 제외**
- 블랙리스트 등록 유저는 적립 대상에서 제외

### 3. ⚡ 게릴라 채널 부스트 (`/채널부스트`)
- 특정 채널에 **포인트 배율**(2배, 3.5배 등 1.0 이상)을 적용해 한시적 이벤트 개최
- 기간 입력은 `10s`, `30m`, `1h`, `2d` 및 `30분`, `1시간`, `2일` 형식 지원 (**최소 10초**, `0` 입력 시 무제한)
- **5초 주기 백그라운드 루프**가 만료를 감시해 자동 해제하고, 해당 채널에 종료 안내 임베드를 발송
- 진행 중인 부스트 목록(채널 · 배율 · 남은 시간) 확인 및 즉시 수동 해제 지원

### 4. 🛒 포인트 상점 (`/상점`, `/상점설정`)
- 포인트로 상품 · 혜택 구매, 구매 시 **디스코드 역할 자동 지급** 가능
- 재고 관리 지원 (`-1` = 무제한, `0` = 품절 처리 및 구매 차단)
- 관리자는 드롭다운 UI로 상품 추가 / 재고 충전 / 삭제 / 목록 확인

### 5. 🎰 럭키 뽑기 (`/뽑기`, `/뽑기설정`)
- 포인트를 소비해 확률 추첨, 당첨 시 **역할 + 포인트 보상** 동시 지급 가능
- **전체 항목의 확률 합이 정확히 100%가 아니면 뽑기 실행 자체가 차단**되어 설정 실수를 방지
- 항목별 재고 관리 및 당첨 시 자동 차감

### 6. 🎫 희귀 바이옴 제보 티켓 (`/제보`, `/제보설정`)
- 채널 링크 · 규칙 동의 모달 제출 시 **제보자와 관리자만 볼 수 있는 비공개 티켓 채널** 자동 생성
- 티켓 생성 시 지정된 **알림 역할 멘션**으로 관리자 호출
- 관리자가 [💰 포인트 지급] 버튼 클릭 시 설정된 기본 포인트(기본값 **500 P**) 지급 후 **버튼 비활성화로 중복 지급 차단**
- [❌ 티켓 닫기] → 유저 권한 제외 및 채널명 변경 → [🗑️ 티켓 삭제]의 **2단계 삭제 절차**
- 버튼은 `timeout=None` 영구 View라 봇 재시작 후에도 정상 동작

### 7. 🚫 포인트 블랙리스트 (`/블랙리스트`)
- 매크로 · 파밍 등 어뷰징 유저를 **포인트 적립 대상에서 제외**
- 버튼 UI로 추가 / 해제 / 목록 새로고침, 등록 사유 기록 지원

### 8. 📋 활동 로그 (`/로그`)
- `🛒 상점 구매` · `🎰 뽑기 당첨` · `🎫 바이옴 제보` · `🛠️ 관리자 조정` 카테고리별 조회
- 페이지당 10건, 최대 5페이지(50건)까지 페이지 이동 버튼으로 열람

### 9. 🔒 비공개 응답 (Ephemeral)
- 개인정보 보호 및 채팅방 도배 방지를 위해 모든 명령어 응답은 **명령어를 입력한 본인에게만** 표시

### 10. 🎛️ 시스템 전원 스위치 (`/인증시스템`)
> 문제가 생겼을 때 **즉시 정지**할 수 있는 비상 스위치입니다. 봇 재시작이 필요 없습니다.

- 인증 · 링크 보호의 현재 상태를 한눈에 보여주고, 버튼으로 각각 또는 한 번에 켜고 끕니다.
- **[🛑 전체 끄기]** 를 누르면 봇이 웹훅 임베드를 전혀 건드리지 않고 인증 버튼도 응답하지 않아,
  **기능이 설치되지 않은 상태와 동일**해집니다.
- 설정은 메모리 캐시에 즉시 반영되므로 **누르는 순간 적용**됩니다.
- 정지 중에는 **이미 게시된 보호 메시지의 버튼도 누구나** 링크를 받습니다.
  정지 상태에서 유저가 링크를 못 받는 일이 없도록, 역할 검사보다 전원 검사를 먼저 수행합니다.
  (이때는 워터마크와 열람 기록도 남기지 않습니다)

> ⚠️ **인증만 끄면 안 됩니다.** 인증을 끄고 링크 보호를 켜두면
> 아직 인증받지 못한 유저가 **인증받을 방법이 없어 링크에 영영 접근하지 못합니다.**
> 평상시 상태로 되돌리려면 반드시 **[🛑 전체 끄기]** 를 사용하세요.
> 이 조합이 되면 `/인증시스템` 화면에 경고가 표시됩니다.

> ℹ️ **되돌릴 수 없는 것 하나**: 정지 이전에 이미 치환된 메시지는 원본으로 복구되지 않습니다.
> 원본 웹훅 메시지는 삭제된 상태이기 때문입니다. 다만 버튼은 누구나 누를 수 있으므로 접근에는 문제가 없습니다.

> ✅ **처음 배포해도 안전합니다**: 보호 채널 목록과 인증 역할이 비어 있는 상태에서는
> 감지 대상도, 인증 패널도 없어 봇이 아무것도 건드리지 않습니다. 설정을 마친 뒤부터 동작합니다.

### 11. 🔐 서버 인증 (`/인증설정`)
> 이 기능은 **포인트 시스템과 완전히 분리된 독립 모듈**입니다. 포인트가 오가지 않고 활동 로그에도 기록되지 않습니다.

- 인증 채널에 전송된 패널의 **[✅ 인증하기] 버튼**으로 지정된 인증 역할이 부여됩니다.
- 패널 제목 · 안내 문구 · 버튼 문구를 관리자가 자유롭게 수정할 수 있습니다.

**인증 조건 (모두 통과해야 역할이 나갑니다)**

| 순서 | 검사 | 설정 | 기본값 |
| :---: | :--- | :--- | :--- |
| 1 | 시스템이 켜져 있는가 | `/인증시스템` | 켜짐 |
| 2 | **필요 역할** 중 하나 이상 보유 | `🎫 인증 필요 역할 관리` | 없음(누구나) |
| 3 | **로블록스 계정 연동** 완료 | `🎮 로블록스 연동 필수 여부` | 꺼짐 |

> ⚠️ **검사 순서가 중요합니다.** 전원 검사가 역할 검사보다 **먼저** 와야 합니다.
> 반대로 두면 시스템을 정지시켰는데도 유저가 거부 사유를 보게 됩니다.

- **필요 역할**은 여러 개 지정할 수 있고 **OR 조건**입니다(하나만 있으면 통과).
  서버에 막 들어온 스나이퍼가 곧바로 인증받는 것을 막는 장치입니다.
- 조건은 **패널 임베드에 그대로 표시**됩니다. 조건을 모른 채 눌렀다 거부당하는 것보다 낫습니다.
- 3번에서 막히면 **[로블록스로 로그인] 버튼이 그 자리에 나옵니다.** 명령어를 따로 찾아갈 필요가 없습니다.

**♻️ 자격 상실 시 자동 회수 (`auto_revoke`, 기본 꺼짐)**

- 필요 역할을 **전부 잃으면** 인증 역할도 자동으로 회수합니다 (`on_member_update`).
- 필요 역할이 하나도 없으면 '자격 상실'을 판단할 수 없으므로 **켜지지 않습니다.**
- ⚠️ 필요 역할을 잘못 지정하면 **멀쩡한 인증자까지 줄줄이 풀립니다.** 그래서 기본은 꺼둡니다.
- 이미 인증된 유저, 역할 미설정, **봇 역할이 인증 역할보다 아래인 경우** 등 실패 원인을 각각 안내합니다.
- `현재 설정 확인`에서 역할 관리 권한과 역할 서열까지 자동 점검합니다.
- 버튼은 고정 `custom_id`의 영구 View라 **봇 재시작 후에도 그대로 동작**합니다.

### 12. 🎮 로블록스 개인서버 링크 보호 (`/링크보호설정`)
> 이 기능도 포인트 시스템과 무관하게 동작하는 **독립 모듈**입니다.
> **로블록스 개인서버(Private Server) 링크**를 인증 유저 전용으로 배포하는 데 최적화되어 있습니다.

지정한 채널에 **웹훅**이 임베드를 올리면, 봇이 이를 감지해 다음과 같이 치환합니다.

```
[원본 웹훅 임베드]                       [봇이 치환한 임베드]
🎮 개인서버 오픈!                        🎮 개인서버 오픈!
roblox.com/games/...?privateServer  →   `🔒 인증된 유저만 입장할 수 있습니다`
                                          ┌──────────────────┐
                                          │ 🎮 개인서버 입장하기 │ ← 클릭 시 역할 검사
                                          └──────────────────┘
```

**📂 감시 대상 지정 — 카테고리 단위 (권장)**

`/링크보호설정` → **감시 카테고리 추가**로 카테고리를 지정하면,
그 안의 **모든 텍스트 채널(비공개 포함)** 이 한 번에 감시 대상이 됩니다.

- 추가 방법이 3가지입니다.
  - **🔎 이름으로 일괄 추가** — `매크로 채널` 입력 → 이름이 겹치는 카테고리를 전부 추가 (가장 빠름)
  - **📂 목록에서 추가** — 드롭다운에서 선택 (최대 25개씩)
  - **🆔 ID로 추가** — 목록에 안 보이는 카테고리를 ID로 직접 추가 (쉼표·줄바꿈·공백 구분)
- 카테고리에 **채널을 새로 만들면 자동으로 감시 대상에 포함**됩니다. 재설정이 필요 없습니다.
- 카테고리 밖의 채널은 **개별 채널 추가**로 따로 지정할 수 있습니다.
- 스레드에 올라온 웹훅 임베드는 **부모 채널 기준**으로 판정합니다.

> ⚠️ **비공개 카테고리 주의**: 봇이 카테고리를 못 보면 **선택 목록에도 나타나지 않고**,
> 설령 ID로 등록해도 메시지가 도착하지 않아 감시가 되지 않습니다.
> 비공개 카테고리는 **카테고리 편집 → 권한**에서 봇 역할에
> `채널 보기` · `메시지 보내기` · `메시지 관리` 를 주세요. 안의 채널이 전부 상속받습니다.
> `현재 설정 및 권한 점검`에서 권한이 부족한 채널을 자동으로 찾아 알려줍니다.

- **감지 대상은 웹훅 메시지 뿐입니다** (`webhook_id` 기준). 일반 유저와 봇 자신의 메시지는 건드리지 않습니다.
- 링크가 들어올 수 있는 **세 곳을 모두** 훑습니다. 매크로마다 링크를 담는 위치가 다르기 때문입니다.

| 매크로 유형 | 링크 위치 | 처리 |
| :--- | :--- | :--- |
| maxstellar's Biome Macro | 임베드 본문의 평문 URL | 잠금 문구로 치환 |
| Coteab Macro | 마크다운 마스킹 링크 `[Join Server](url)` | 문구만 남기고 URL 제거 |
| MultiScope | **[Join Server] 링크 버튼(컴포넌트)** | 버튼째 제거 후 보호 버튼으로 교체 |

- 임베드의 **제목 하이퍼링크 · 본문 · 필드 · 작성자 링크**와 **메시지 본문**, **링크 버튼**에서 URL을 모두 추출합니다.
- 컴포넌트는 중첩될 수 있어 재귀적으로 탐색하므로, 버튼이 여러 겹으로 감싸여 있어도 놓치지 않습니다.
- **이미지 · 썸네일 URL은 그대로 보존**되어 임베드 모양이 깨지지 않습니다.
- 링크가 하나도 없는 임베드는 **원본을 그대로 둡니다**.
- **로블록스 링크만 보호합니다** (기본값). 매크로 임베드에는 제작자 홍보 사이트 링크가
  함께 들어있는 경우가 많은데, 그런 링크까지 가로채면 버튼이 엉뚱한 주소로 연결됩니다.
  - 로블록스가 아닌 링크는 **원문 그대로 남겨둡니다**.
  - 로블록스 링크가 하나도 없는 메시지는 **아예 건드리지 않습니다**.
  - 링크가 여러 개면 **개인서버 링크가 버튼의 대표 링크**가 되도록 정렬합니다.
  - `/링크보호설정` → **🎮 로블록스 링크만 보호** 에서 끌 수 있습니다(권장하지 않음).
- 원본은 삭제 후 재게시되며, 누가 보냈는지 알 수 있도록 **원본 웹훅의 이름 · 프로필이 임베드 작성자란에 유지**됩니다.

#### ⚡ 속도 설계 (수백 명 동시 클릭 대비)

개인서버는 자리 경쟁이 벌어지므로, 버튼 클릭부터 입장까지의 지연을 최소화했습니다.

| 처리 단계 | 방식 |
| :--- | :--- |
| 링크 조회 | **메모리 캐시** (봇 재시작 후 첫 클릭만 DB 조회) |
| 인증 설정 조회 | **메모리 캐시** (저장 시 즉시 갱신되어 값이 어긋나지 않음) |
| 역할 검사 | 이미 메모리에 있는 `interaction.user.roles` 사용 — 추가 API 요청 없음 |
| 실제 이동 | **로블록스로 직행하는 링크 버튼** — 중계 서버를 거치지 않음 |
| 열람 기록 | 응답을 보낸 **뒤** 백그라운드 처리 — 클릭 속도에 영향 없음 |
| DB 쓰기 | **워커 스레드로 분리** — 이벤트 루프를 막지 않음 (아래 참고) |

> ⚠️ **동기 드라이버 주의**: `pymongo`는 동기 라이브러리라 `async` 함수에서 그냥 호출하면
> 그동안 봇 전체가 멈춥니다. 개인서버는 정원 20명을 두고 80명이 몰릴 수 있는데,
> 클릭 1회당 DB 쓰기가 여러 번 일어나므로 이 정지가 누적되면
> **디스코드 상호작용 3초 제한을 넘겨 "상호작용에 실패했습니다"가 발생**합니다.
> 그래서 모든 DB 호출을 워커 스레드(`asyncio.to_thread`)로 넘깁니다.
>
> | 동시 클릭 | 분리 전 | 분리 후 |
> | ---: | ---: | ---: |
> | 20명 | 741ms 정지 | 48ms |
> | 80명 | **2,970ms 정지** | **155ms** |
>
> 워터마크는 유저마다 고정값이라, 이미 저장된 유저의 재클릭은 쓰기를 건너뜁니다.

#### 🔀 중계 링크 + 신원 게이트 (`relay_links`)

> ⚠️ 초기 설계에서는 속도 때문에 중계를 **일부러 쓰지 않았습니다.** 나중에 뒤집었습니다.
> 아래에 뒤집은 이유와 감수한 대가를 남깁니다.

로블록스 주소를 버튼에 그대로 넣으면, 유저가 **버튼을 우클릭해 주소를 복사**하는 것만으로
링크가 그대로 빠져나갑니다. 워터마크로 사후 추적은 되지만 유출 자체는 막지 못합니다.

그래서 버튼이 가리키는 주소를 **우리 서버의 1회용 중계 주소**로 바꿨습니다.

```
버튼 클릭 → 봇이 1회용 토큰 발급 → https://<서비스>/j/<token> 전달
          → 클릭 → 디스코드 신원 확인(OAuth) → 발급 대상 본인인지 검증
          → 로블록스로 302 리다이렉트 (토큰 즉시 소멸)
```

| 항목 | 값 | 이유 |
| :--- | :--- | :--- |
| 토큰 수명 | 90초 | 자리 경쟁에 들어가긴 충분하고, 퍼뜨렸을 땐 이미 늦은 시간 |
| 사용 횟수 | **1회** | 한 번 쓰면 즉시 잠깁니다. 다시 들어가려면 버튼을 다시 누릅니다 |
| 신원 확인 | 디스코드 OAuth | **발급받은 본인만** 열립니다. 남에게 넘겨도 열리지 않습니다 |
| 메모리 상한 | 5,000개 | 넘으면 오래된 것부터 버립니다 |

> 🕒 **OAuth 왕복 중 토큰이 죽는 문제**가 있었습니다. 신원 확인 예산(600초)이
> 토큰 수명(90초)보다 길어서, 로그인에 **성공하고도** "만료되었습니다"가 떴습니다.
> 지금은 게이트로 내보내기 직전에 왕복 예산만큼 수명을 늘립니다. 1회용과 소유자
> 검증은 그대로라 유출 내성은 유지됩니다.

**감수한 대가 — Render 콜드 스타트**

Render 무료 플랜은 유휴 시 잠들어 **첫 요청에 30~50초**가 걸릴 수 있습니다.
자리 경쟁 상황에서는 치명적이라, 원래 이 이유로 중계를 배제했었습니다.
신원 게이트의 가치가 더 크다고 판단해 뒤집었지만, **이 위험은 여전히 남아 있습니다.**
문제가 되면 `/링크보호설정`에서 `relay_links`를 끄면 즉시 예전 방식(직접 링크)으로 돌아갑니다.

#### 🔍 유출 추적

무엇이 잡히고 무엇이 안 잡히는지 명확히 구분됩니다.

| 유출 경로 | 탐지 | 방법 |
| :--- | :---: | :--- |
| 서버 내 다른 채널에 붙여넣기 | ✅ 즉시 | 봇이 모든 채널의 메시지를 검사 |
| 링크 주소를 복사해 남에게 전달 | ✅ 차단 | 중계 토큰이 **1회용 + 본인 전용**이라 열리지 않음 |
| DM · 카카오톡 등 외부 유출 | ⚠️ 사후 | 워터마크로 최초 수령자 역추적 |
| **명단에 없는 사람이 게임에 접속** | ⚠️ 사후 | **로블록스 연동 명단과 대조** (아래 참고) |
| 스크린샷 · 구두 전달 | ❌ | 탐지 불가 |

> 🎯 **서버 밖 유출은 자동으로 감지되지 않습니다.** 봇은 디스코드 밖을 볼 수 없습니다.
> 대신 **게임 안 플레이어 목록**과 연동 명단을 대조하는 것이 현실적인 유일한 경로입니다.
> 여러 사건에서 반복되는 이름을 교집합으로 좁혀 나가는 방식입니다.

**🔖 워터마크 (유출자 추적)**

버튼을 누른 유저마다 링크 뒤에 다른 표식이 붙습니다.

```
https://www.roblox.com/games/920587237/Adopt-Me?privateServerLinkCode=xxxxx#hbh-d41ab726
                                                                          └─ 유저별 표식
```

- `#` 뒤 **프래그먼트는 서버로 전송되지 않으므로**, 로블록스 접속 동작에 전혀 영향이 없습니다.
- 링크를 복사해 퍼뜨리면 표식이 **그대로 따라갑니다**.
- 유출된 링크가 발견되면 표식으로 **최초 수령자가 누구인지** 즉시 나옵니다.
- 같은 유저는 항상 같은 코드, 다른 유저는 다른 코드가 나옵니다 (길드+유저 해시).

**🚨 서버 내 유출 자동 감지**

- 봇이 **모든 채널의 메시지**를 검사해, 보호 중인 링크가 다시 게시되면 즉시 잡아냅니다.
- 우회 시도를 다음까지 잡아냅니다.

| 유출 방식 | 감지 |
| :--- | :---: |
| 링크 그대로 붙여넣기 | ✅ |
| 워터마크(`#hbh-…`)를 지우고 붙여넣기 | ✅ |
| 게임 이름·파라미터를 바꿔 붙여넣기 | ✅ |
| **URL 없이 개인서버 코드만 전달** | ✅ |
| 코드를 대문자로 바꿔 전달 | ✅ |

- **개인서버 코드 기준**으로 매칭하므로 URL 표기를 바꿔도 우회되지 않습니다.
- 관계없는 링크나 다른 개인서버 코드는 오탐하지 않습니다.
- 감지 시 **메시지를 자동 삭제**하고, 게시자와 워터마크 추적 결과를 로그에 남깁니다.
- 웹훅 원본과 봇 자신의 재게시는 유출로 처리하지 않습니다.

**🎯 외부 유출 추적 (`유출 링크 추적`)**

서버 밖(카카오톡, 다른 디스코드, 커뮤니티 등)에서 유출된 링크를 발견했을 때 사용합니다.

```
/링크보호설정 → 🎯 유출 링크 추적 (워터마크 조회)
   → 발견한 링크 또는 코드 8자리를 붙여넣기
   → 🎯 최초 수령자 · 서버 재적 여부 · 최근 열람 기록 표시
```

- 링크 전체를 붙여넣어도 되고, `#hbh-` 뒤의 코드 8자리만 넣어도 됩니다.
- 표식이 지워진 링크라면 **링크 열람 기록**으로 해당 시간대 수령자를 좁힐 수 있습니다.

> ⚠️ 워터마크는 **링크를 받아간 사람**을 가리킵니다. 그 사람이 직접 퍼뜨렸을 수도 있고,
> 그 사람의 화면이나 기기에서 제3자가 가져갔을 수도 있습니다. 조치 전에 확인이 필요합니다.

**📋 로그 채널**

`/링크보호설정` → **📋 로그 채널 설정**으로 채널을 지정하면 아래 기록이 실시간 전송됩니다.

- **드롭다운에서 선택** — 목록에서 채널을 고릅니다.
- **🆔 채널 ID로 입력** — 목록에 안 보이는 비공개 채널을 ID로 직접 지정합니다.

두 방식 모두 저장 직후 봇의 `채널 보기` · `메시지 보내기` · `링크 첨부` 권한을 점검해,
권한이 없으면 경고를 표시합니다.

| 이벤트 | 내용 |
| :--- | :--- |
| 🛡️ 링크 사용 시작 | **누군가 처음 링크를 사용한 순간** 임베드 1개. 임베드 제목 · 링크 요약 · **사용 인원** · 원문 바로가기 |
| 🚨 링크 유출 감지 | **게시한 유저** · **워터마크로 추적된 원 수령자** · 자동 삭제 여부 |

> 💡 **아무도 안 누른 링크는 로그를 남기지 않습니다.** 바이옴은 10분마다 바뀌어 임베드가
> 계속 올라오지만, 실제로 눌리는 것은 극소수입니다. 보호할 때마다 로그를 보내면
> 로그 채널이 `0명 사용` 알림으로 뒤덮이므로, **처음 눌린 순간**에만 만듭니다.

**👥 임베드별 사용 인원 집계**

실제로 사용된 링크마다 로그 임베드가 하나씩 생기고, 그 임베드에 **사용 인원이 누적**됩니다.

```
🛡️ 링크 사용 시작
📌 임베드      Biome Started - RAINY
🔗 링크        🎮 코드 c26a…a0
👥 사용 인원    12명이 이 링크를 사용했습니다.
🔍 보호된 메시지  바로가기
┌────────────────┐
│ 👥 링크 사용 유저 │ ← 관리자만 클릭 가능
└────────────────┘
```

- **임베드마다 따로 집계**됩니다. 다른 알림의 사용자와 섞이지 않습니다.
- 같은 사람이 여러 번 눌러도 **인원은 1명**으로 세고, 명단에 `×3`처럼 횟수를 표시합니다.
- 버튼을 누르면 사용자 명단(최근순 25명)과 마지막 사용 시각이 나옵니다.
- 버튼은 고정 `custom_id`의 영구 View라 **봇 재시작 후에도 동작**합니다.
- 수십 명이 동시에 눌러도 로그 임베드는 **정확히 하나만** 만들어집니다.

> 💡 **클릭마다 로그 메시지를 보내지 않습니다.** 수백 명이 몰릴 때 로그 채널이 도배되고
> 레이트 리밋에 걸리기 때문입니다. 사용 인원 표시는 **10초에 한 번** 갱신하되,
> 몰림이 끝난 뒤 **마지막 값으로 한 번 더 갱신**하므로 최종 인원은 정확합니다.
> 언제든 버튼으로도 확인할 수 있습니다.

기록은 `/링크보호설정` → **링크 열람 기록** / **유출 감지 기록**에서도 조회할 수 있으며,
관리자 화면에서도 서버 코드는 `4829…05`처럼 일부만 표시됩니다.

> ⚠️ **필요 권한**: 대상 채널에 봇의 `메시지 관리`(원본 삭제용)와 `메시지 보내기` 권한이 필요합니다.
> 권한이 없으면 원본을 건드리지 않고 콘솔에 경고만 남깁니다. `현재 설정 및 권한 점검`에서 채널별로 확인할 수 있습니다.
>
> ⚠️ **구조적 한계**: 디스코드 임베드는 모든 유저에게 동일하게 렌더링되므로 *유저별로 다른 임베드*는 만들 수 없습니다.
> 또한 봇은 메시지가 전송된 **뒤에** 감지하므로 원본이 **약 0.2~0.5초간 보였다가 사라집니다**.
> 이 노출조차 막으려면 웹훅을 비공개 채널로 보내고 봇이 공개 채널로 미러링하는 구조가 필요합니다.
>
> ⚠️ **복사 자체는 막을 수 없습니다.** 브라우저가 링크를 열려면 URL을 알아야 하므로, 열람 권한이 있는 사람은
> 어떤 방식으로든 URL을 추출할 수 있습니다. 이 시스템의 목표는 *차단*이 아니라 **캐주얼한 복사 억제 + 유출 시 추적**입니다.
> 링크가 유출되면 로블록스에서 **개인서버 링크를 재발급**하고 웹훅으로 새 링크를 올리는 것이 가장 확실한 대응입니다.
>
> 💡 **1클릭으로 줄이려면**: 보호 채널 자체를 인증 역할만 볼 수 있게 잠그면 중간 버튼이 필요 없어져,
> 임베드의 링크를 바로 누르는 **1클릭 · 0지연** 구성이 됩니다. 대신 미인증 유저는 채널 존재 자체를 못 봅니다.

### 13. 🎮 로블록스 계정 연동 (`/로블록스연동`)
> 이 기능도 포인트 시스템과 무관한 **독립 모듈**입니다.

**왜 만들었는가.** 서버 **안**의 유출은 봇이 전부 잡습니다. 하지만 서버 **밖**으로 나간
유출은 디스코드에서 볼 방법이 없습니다. 유일하게 남는 단서가 **게임 안 플레이어 목록**입니다.
링크를 받아간 사람들의 로블록스 아이디를 알고 있으면, 개인서버에 들어와 있는 사람 중
**명단에 없는 이름**을 골라낼 수 있습니다.

**왜 닉네임 입력이 아닌 OAuth인가.** 닉네임을 그냥 받으면 **남의 이름을 적어 사칭**할 수 있어
명단 자체가 무의미해집니다. 로블록스 **공식 OAuth**로 본인임을 보증받습니다.

```
/로블록스연동 → [로블록스로 로그인] → 로블록스 공식 동의 화면
              → 아이디 · 유저명만 수신 → 연동 완료
```

| 항목 | 내용 |
| :--- | :--- |
| 요청 권한 | `openid` `profile` — **아이디와 유저명만**. 비밀번호 · 로벅스 · 인벤토리 접근 없음 |
| 제약 | 로블록스 계정 하나 ↔ 디스코드 계정 하나 (**유니크 인덱스로 DB에서 강제**) |
| 나이 | 로블록스 OAuth는 **만 13세 이상**만 사용 가능 |
| 저장 값 | `roblox_id` `roblox_name` `linked_at` `roblox_created_at` |

> ⚠️ `roblox_created_at`은 ISO 문자열이 아니라 **유닉스 타임스탬프(int)** 입니다.
> 나중에 "계정 나이 N일 이상" 조건을 붙일 때 문자열로 파싱하면 안 됩니다.

**🔄 계정 교체 확인 · 알림**

- 이미 연동된 상태에서 `/로블록스연동`을 부르면 **곧바로 로블록스로 보내지 않고** 확인부터 받습니다.
  로블록스 동의 화면은 로블록스가 만든 페이지라 "이미 연동됨" 같은 안내를 넣을 수 없기 때문입니다.
- 확인을 눌러야 로그인 링크가 생성되므로, 취소하면 서버에 대기 항목이 남지 않습니다.
- ⚠️ 로블록스 동의 화면은 **지금 브라우저에 로그인된 계정**을 그대로 씁니다.
  이걸 모르면 엉뚱한 계정으로 갈아타 놓고 알아채지 못하므로, 화면에서 경고합니다.
- 계정이 실제로 바뀌면 **로그 채널에 이전/이후 계정이 기록**됩니다 (`roblox_relink_alert`, 기본 켜짐).
  갑작스러운 계정 교체는 그 자체로 확인해 볼 만한 신호입니다.

**🔍 명단 대조 (`/연동명단`, `/연동조회`)**

`/연동조회`는 **어느 방향으로든** 찾습니다. 게임에서 본 낯선 이름을 역으로 확인하는 것이 주 용도입니다.

| 검색어 | 결과 |
| :--- | :--- |
| 로블록스 유저명 (일부만 입력해도 됨) | 해당하는 멤버들 |
| 디스코드 ID · 멘션 | 그 사람의 로블록스 계정 |
| 로블록스 숫자 ID | 그 계정의 주인 |

| 조회 결과 | 해석 |
| :--- | :--- |
| 나옴 | 우리 멤버 |
| **안 나옴** | ⚠️ 링크 유출 의심 (또는 아직 연동 안 한 멤버) |
| 나오는데 `⚠️ 서버에 없음` | **가장 의심스러운 경우** — 링크만 받고 서버를 나간 패턴 |

> 검색어는 정규식 이스케이프 처리됩니다. `.*` 같은 것을 넣어도 명단이 통째로 나오지 않습니다.

> ⚠️ **로블록스 앱 심사 전에는 10명까지만** 연동할 수 있습니다.
> 승인 전에 `🎮 로블록스 연동 필수`를 켜면 **11번째 유저부터 인증을 받지 못합니다.**
> 그래서 OAuth가 설정되지 않은 상태에서는 이 옵션이 아예 켜지지 않도록 막아 두었습니다.

### 14. 🧭 퀘스트 (`/퀘스트`, `/퀘스트설정`)

채팅과 출석만으로는 포인트가 잘 모이지 않아 만든 **수급처**입니다.

**퀘스트는 유저마다 다르게, 매일 무작위로** 뽑힙니다. 모두가 같은 목록을 보면
"오늘 퀘스트 뭐임" 한 번 물으면 끝이라 매일 뽑는 의미가 옅어집니다.

| 주기 | 종류 |
| :--- | :--- |
| **일일** (매일 3개 추첨) | 채팅 N회 · 출석하기 · **랜덤 채널**에서 N회 대화 · 뽑기 N회 · 출석 선착순 N등 |
| **주간** (매주 2개 추첨) | 이번 주 N일 출석 · 채팅 N회 · 뽑기 N회 · **랜덤 채널** N회 |

```
📋 나의 퀘스트

☀️ 오늘의 퀘스트 · 개당 +150 P
🎁 출석하기            1/1  ████████████  ← 받을 수 있습니다
🎁 뽑기 2회 돌리기      2/2  ████████████  ← 받을 수 있습니다
▫️ #잡담 에서 10회 대화   6/10 ███████░░░░░

📅 이번 주 퀘스트 (일~토) · 개당 +800 P
▫️ 이번 주 5일 출석      3/5
▫️ 이번 주 채팅 150회    60/150

        [🎁 보상 받기]
```

- 일일은 **매일 밤 12시(KST)**, 주간은 **일요일 밤 12시**에 새로 시작됩니다.
- 완료한 퀘스트는 **버튼 한 번에** 모두 받습니다.
- 진행도는 다른 기능(`chat_reward` `checkin` `gacha`)이 활동할 때 올려 줍니다.
  채팅 진행도는 **포인트 지급과 같은 필터를 통과한 메시지만** 셉니다.
  기준이 다르면 "채팅했는데 퀘스트가 안 오른다"는 혼란이 생깁니다.

#### 🎲 저장하지 않고 뽑습니다

무작위 씨앗이 `길드:유저:날짜` 라, **같은 사람은 하루 동안 같은 목록**을 보되
사람마다 다른 조합을 받습니다. 저장이 필요 없으므로 1,245명분 문서를 매일
쓰는 대신 계산으로 해결하고, 봇이 재시작해도 목록이 흔들리지 않습니다.

> 분포 검증: 유저 2,000명 기준 각 종류가 58~62% 로 나옵니다(기대 60%).
> 한 유저를 30일 돌려도 특정 종류에 몰리지 않습니다.

#### 🎉 이벤트 퀘스트

기간을 정해 여는 특별 퀘스트입니다. **보상으로 포인트와 역할을 줄 수 있어**
기념 역할 배포에 쓸 수 있습니다. 진행도는 기간 내내 누적됩니다.

**두 가지 방식**

```
단계별 — 하나의 조건을 여러 단계로
  🎁 채팅 100회    →  +500 P
  🎁 채팅 300회    →  +1,500 P
  🎁 채팅 1,000회  →  @추석기념 역할
  (단계마다 따로 받습니다)

모두달성 — 여러 조건을 전부 깨야 보상
  ✅ 채팅 200회   ✅ 뽑기 10회   ▫️ 출석 5일
  전부 달성 시  →  +2,000 P · @추석기념 역할
```

| 항목 | 값 |
| :--- | :--- |
| 조건 | 채팅 · 뽑기 · 출석 |
| 단계 | 최대 5개 |
| 조건 (모두달성) | 최대 4개 |
| 보관 | 길드당 20개 |

- `/퀘스트설정` → `🎉 이벤트 퀘스트` 에서 만들고 관리합니다.
- 기간은 **KST 날짜 기준이며 양끝을 포함**합니다.
- 기간 안이어도 **잠시 끌 수 있습니다** (준비 중이거나 문제가 생겼을 때).
- 진행도는 이벤트별로 따로 쌓입니다. 그 조건을 쓰지 않는 이벤트에는
  카운트되지 않습니다.
- 역할 지급이 실패해도(봇 권한 부족 등) **포인트는 이미 지급**되며,
  무엇이 안 됐는지 알려줍니다.

> ⚠️ 이벤트 진행도 문서의 TTL 은 **마지막 활동 기준**입니다. `created` 를
> 고정하면 긴 이벤트가 끝나기 전에 진행도가 지워집니다.

#### 🔧 관리자 전용 테스트 모드

공개 전에 관리자끼리 돌려보기 위한 모드입니다.

- 켜면 **관리자만** `/퀘스트` 를 쓸 수 있습니다.
- 일반 유저에게는 **꺼진 것과 똑같이** 보여, 준비 중이라는 사실이 드러나지 않습니다.
- 진행도는 평소처럼 쌓이므로 **공개 후 그대로 이어집니다.**

#### 🎲 랜덤 채널 퀘스트

채널 후보를 **여러 개** 등록해 두면, 유저마다 그중 **하나가 무작위로** 배정됩니다.

```
유저 A   #잡담 에서 10회 대화하기
유저 B   #공략 에서 10회 대화하기
유저 C   #자랑 에서 10회 대화하기
```

- 같은 사람은 그날 하루 같은 채널을 봅니다(씨앗이 고정이라).
- 진행도는 **채널별로 따로** 셉니다 (`ch_<채널ID>`). 사람마다 목표 채널이
  다르므로 하나의 카운터로는 셀 수 없습니다.
- 후보가 많을수록 사람들이 여러 채널로 흩어집니다. 하나만 등록하면
  모두 같은 채널을 받습니다(예전 동작).
- 후보가 하나도 없으면 채널 퀘스트는 **출제되지 않습니다.**

> 검증: 후보 4개 · 유저 600명 기준 각 채널이 131~166회로 고르게 배정됩니다
> (기대 150).

#### 🤝 서버 공동 목표

개인 퀘스트와 별개로, **서버 전체가 함께 채우는 목표**입니다.

```
🤝 오늘의 서버 공동 목표
서버 전체가 함께 채팅 2,000회 를 채우면
오늘 퀘스트에 참여한 모두에게 +300 P 가 지급됩니다.

📊 진행 상황
`740 / 2,000`  (37%)
███████░░░░░░░░░░░░░
```

- 지정한 채널에 **메시지 하나가 2분마다 갱신**됩니다. 수정 방식이라 도배되지
  않고 알림도 울리지 않습니다.
- `/퀘스트` 를 켜지 않은 사람의 채팅도 전부 카운트됩니다(서버 합계).
  다만 **보상은 직접 받아야** 합니다 — 6,500명에게 일괄 지급하면 디스코드
  요청 제한에 걸립니다.

**🔒 무임승차 방지 — 본인도 최소한은 채워야 합니다**

목표치의 일정 비율(`goal_min_percent`, 기본 2%)을 **달성 전에** 쳐야 받을 수
있습니다. 이미 목표가 100% 달성된 뒤에 참여한 유저(늦참자)에게는 더 높은
비율(`goal_late_min_percent`, 기본 4%)을 요구하여 무임승차를 방지하고
선발대 기여자의 성취감을 보호합니다.

```
[목표 2,000회 기준]
달성 전 기본 2%  ->  목표 달성 전 본인이 40회 이상 참여 시 즉시 수령
달성 후 늦참 4%  ->  목표 달성 후 참여자는 본인 총 채팅 80회 이상이어야 수령
```

목표치에 비례하므로 **목표를 바꿔도 따로 조정할 필요가 없습니다.**
`0` 으로 두면 추가 페널티 없이 기본 조건으로 적용됩니다.

`/퀘스트` 에는 자기 진행도와 참여 상태가 함께 보입니다.

```
▫️ 진행 중: 내 채팅 15/40 (목표의 2% 참여 필요)
🎁 달성 후 선발대: 내 채팅 45/40 (달성 전 기여 완료 · 받을 수 있습니다)
🔒 달성 후 늦참 미달: 내 채팅 20/80 (목표 달성 후 참여는 4% (80회) 필요)
🎁 달성 후 늦참 달성: 내 채팅 80/80 (달성 후 참여 기준 달성 · 받을 수 있습니다)
```

### 15. 💾 백업 · 복원 (`/백업설정`)
> **포인트는 이 봇의 존재 이유입니다.** 로직 사고나 실수로 초기화됐을 때 되돌릴 수단을 제공합니다.

| 기능 | 설명 |
| :--- | :--- |
| 📸 지금 백업하기 | 현재 포인트를 즉시 스냅샷으로 저장 |
| 📋 백업 목록 보기 | 보관 중인 시점 · 인원 · 합계 확인 |
| 📥 파일로 내려받기 | JSON 파일로 받아 **서버 밖에** 보관 (권장) |
| ♻️ 백업으로 복원하기 | 특정 시점의 포인트로 되돌리기 |

- **매일 새벽 5시(KST) 자동 백업**되며, 최근 **30개**까지 보관됩니다 (1회 약 40KB).
- 복원 시 **복원 직전 상태를 자동으로 백업**하므로, 잘못 복원해도 다시 되돌릴 수 있습니다.
- 백업 이후 새로 들어온 유저는 **건드리지 않습니다.** 정당하게 쌓은 포인트가 지워지지 않도록 한 선택입니다.
- 복원은 되돌리기 어려운 작업이라 **내용 확인 → 확인 버튼**의 2단계를 거칩니다.

> ⚠️ **DB 안의 백업만 믿으면 안 됩니다.** 스냅샷은 같은 MongoDB 클러스터에 저장되므로,
> **클러스터나 계정 사고가 나면 백업도 함께 사라집니다.**
> `📥 파일로 내려받기`로 받은 파일을 PC·클라우드 등 서버 밖에 주기적으로 보관하세요.
> MongoDB Atlas 무료 티어(M0)에는 자동 백업 기능이 없습니다.

> 💡 **권한 최소화 권장**: 봇이 쓰는 DB 계정에 `atlasAdmin` 같은 관리자 권한이 있으면,
> 연결 문자열이 유출됐을 때 전 데이터가 삭제될 수 있습니다.
> `krbiomehuntbot` DB에 대한 **`readWrite` 권한만** 가진 전용 계정을 쓰세요.

### 16. 🛡️ 무인 운영 (자가 감시 · 자동 복구)

> 관리자가 **오래 자리를 비울 수 있다**는 전제로 만든 장치들입니다.
> 사람이 알아채고 손을 쓰는 것을 기대하지 않고, 스스로 감지하고 스스로 재시작합니다.

#### 🧟 가장 위험한 것은 죽는 게 아니라 **좀비 상태**입니다

Flask 와 디스코드 봇은 **같은 프로세스의 다른 스레드**입니다. 디스코드 연결만 끊기면
Flask 는 멀쩡히 200 을 돌려줍니다. 외부 감시 서비스는 정상으로 판정하고, **아무도 모르는 채**
봇만 멈춰 있습니다. 죽는 것보다 나쁩니다 — 죽으면 호스팅이 재시작이라도 하니까요.

그래서 `/health` 가 **디스코드 연결 상태를 반영**합니다.

```
GET /health
{"status":"ok","connected":true,"ready":true,"guilds":1,
 "latency_ms":80.4,"storage":"mongo","extensions":"12/12","commands":28}
```

| 상태 | 응답 | 이어지는 동작 |
| :--- | :---: | :--- |
| 정상 | `200` | — |
| 기동 후 3분 이내 | `200` | 유예 (부팅 중 오탐 방지) |
| 연결 끊긴 지 4분 | **`503`** | 외부 감시 서비스가 알림 발송 |
| 연결 끊긴 지 5분 | — | **봇이 스스로 재시작** (`os._exit(1)`) |

`watchdog` 루프가 60초마다 확인합니다. discord.py 는 알아서 재접속하므로,
**그걸로도 회복이 안 되는 경우만** 여기까지 옵니다.

> ⚠️ 종료는 반드시 **0 이 아닌 코드**로 해야 합니다. 0 으로 끝나면 호스팅이
> '정상 종료'로 보고 다시 띄우지 않을 수 있습니다. `sys.exit()` 은 예외라서
> 이벤트 루프나 남의 `except` 절에 먹힐 수 있어 `os._exit()` 를 씁니다.

#### 💾 DB 에 접속하지 못하면 **차라리 죽습니다**

`MONGO_URI` 가 설정돼 있는데 접속에 실패하면 **기동을 중단**합니다.

폴백(로컬 JSON)으로 조용히 넘어가면 봇은 정상처럼 보이는데, Render 파일시스템은
휘발성이라 재시작 때 포인트가 전부 사라집니다. 무인 운영에서는 **며칠치가 날아가도
아무도 눈치채지 못합니다.** 틀린 데이터로 도는 것보다 잠깐 멈추는 편이 낫습니다.

멈춰 있으면 호스팅이 재시작을 반복하고, Atlas 가 돌아오면 저절로 복구됩니다.

#### 📟 상태 임베드 (`/백업설정` → 🔔 봇 상태 알림 채널)

**메시지 하나를 1분마다 수정**합니다. 매번 새로 보내면 채널이 도배되고 정작 중요한
신호가 묻히기 때문입니다. 메시지 ID 를 DB 에 두고 계속 편집하므로 알림이 울리지 않습니다.

```
🟢 봇 상태 — 정상
💽 포인트 저장  ⏱️ 연속 가동  📶 응답 속도
✅ MongoDB      3일 5시간     80 ms
⚙️ 기능         🔌 연결       📋 명령어
12/12개         ✅ 정상       28개
🔁 누적 재시작   💾 마지막 전체 백업   🕒 최근 기동 (최근 5회)
6회 · `a1b2c3`  2026-08-29 05:00

1분마다 갱신 · 아래 시각이 멈춰 있으면 봇이 멈춘 것입니다
```

**갱신 시각 자체가 생존 신호입니다.** 봇이 멈추면 갱신도 멈추므로, 시계가 굳어 있는
것만 보고도 이상을 알 수 있습니다.

| 색 | 의미 |
| :---: | :--- |
| 🟢 | 정상 |
| 🟡 | 재연결 중 |
| 🔴 | 포인트 저장 이상 · 기능 누락 · 크래시 루프 |

**`기능 12/12`** — 분모는 `cogs/` 폴더의 파일 수입니다. 하드코딩이 아니라 기능을
추가하면 저절로 늘어납니다. 하나라도 실패하면 `11/12 🚨` 와 함께 **빠진 기능 이름**이
그대로 표시됩니다.

**크래시 루프 판정** — 최근 60분 안에 **같은 커밋**으로 3번 이상 켜졌을 때만 경고합니다.
재배포는 커밋이 매번 바뀌므로 걸리지 않습니다. 둘은 대응이 정반대라 반드시 구분해야 합니다.
(커밋 해시는 `.git` 에서 직접 읽습니다 — Oracle 에는 호스팅이 넣어주는 변수가 없어, 예전에 이 경보가 통째로 무력했던 적이 있습니다)

#### 📡 외부 감시 (UptimeRobot)

봇의 상태 임베드는 **"내가 죽었다"고 말할 수 없습니다.** 죽었으니까요.
그걸 알려주는 것이 외부 감시입니다. 둘은 서로의 사각지대를 메웁니다.

```
감시 주소   https://<서비스>/health
감시 간격   5분
알림        Discord 웹훅 (Down/Up 둘 다 켜기)
```

| 상황 | 상태 임베드 | 외부 감시 |
| :--- | :---: | :---: |

| 좀비 · 완전 사망 | 갱신 멈춤 | **Down 알림** |
| 자동 재시작 성공 | 다시 갱신 | **Up 알림** |

> `Up events` 를 꼭 켜세요. 복구 알림이 없으면 "아직도 죽어 있나"를 알 수 없습니다.

#### 🗄️ 백업 3중화

| 위치 | 주기 | 담기는 것 | 막아주는 사고 |
| :--- | :--- | :--- | :--- |
| Atlas 스냅샷 | 매일 05:00 · 30개 | 포인트만 | 로직 사고 · 실수 |
| **디스코드 채널** | 매일 05:00 | **DB 전체** | 클러스터 · 계정 · PC 사고 |
| PC 파일 | 수동 | DB 전체 | 디스코드 사고 |

채널 업로드는 `/백업설정` → `📡 전체 백업 채널 설정` 으로 켭니다.
파일 형식이 `tools/full_backup.py` 와 같아, **채널에서 받은 파일을 그대로 복원**에
넣을 수 있습니다.

```bash
python tools/full_backup.py restore <파일> --all --yes
```

> 🔒 백업 파일에는 **유저 ID · 포인트 · 워터마크**가 들어 있습니다.
> 업로드 채널은 반드시 관리자 전용 비공개로 두세요.

#### 🧰 운영 도구 (`tools/`)

```bash
python tools/full_backup.py dump              # 전체 백업 -> backups/
python tools/full_backup.py verify            # 파일 vs DB 대조
python tools/full_backup.py restore <파일> --only verify_settings --yes
python tools/check_db_user.py                 # DB 계정 권한 점검
python tools/migrate_cluster.py --yes         # 클러스터 이전 (MONGO_URI_OLD -> MONGO_URI)
```

- 복원은 `--yes` 없이는 **계획만 출력**하고 DB 를 건드리지 않습니다.
- 어떤 복원이든 직전에 현재 상태를 `pre-restore_*` 로 자동 백업합니다.
- 기본은 **덮어쓰기(upsert)** 라 복원 이후 쌓인 데이터가 사라지지 않습니다.
  파일 시점으로 정확히 되돌리려면 `--wipe` 를 명시해야 합니다.
- 복원은 `bulk_write(ReplaceOne, upsert)` 라 **봇이 켜진 상태에서도** 안전합니다.

### 17. ☁️ 클라우드 데이터베이스 (MongoDB)
- MongoDB Atlas 연동으로 재배포 · 재시작에도 데이터 보존
- **DB 연결 실패 시 로컬 JSON으로 자동 폴백**되어 봇이 중단되지 않음
- 모든 데이터가 **길드(서버) 단위로 격리**되어 멀티 서버 운영 가능

#### 🧹 자동 청소 (TTL)

바이옴이 10분마다 바뀌어 보호 임베드가 하루 300건 넘게 쌓이므로,
**MongoDB가 60초마다 스스로 오래된 문서를 지웁니다.** 봇이 꺼져 있어도 동작하며,
별도 청소 코드나 스케줄러가 필요 없습니다.

| 데이터 | 보관 | 기준 |
| :--- | :---: | :--- |
| 보호 링크 (`protected_links`) | **7일** | 생성 시점 |
| 사용 인원 집계 (`link_usage`) | **30일** | **마지막 사용 시점** — 계속 쓰이면 만료 안 됨 |
| 로그 참조 (`log_references`) | **30일** | 마지막 갱신 시점 |
| 링크 열람 기록 (`link_clicks`) | 최근 **500건** | 건수 상한 |
| 유출 감시 코드 · 워터마크 | **영구** | 유출 추적은 오래 뒤에도 필요 |

> ⚠️ **7일이 지난 임베드의 버튼은 동작하지 않습니다.** 눌러도
> `링크 정보를 찾을 수 없습니다`가 표시됩니다. 바이옴은 2~10분이면 끝나므로
> 실사용에는 영향이 없지만, **오래된 알림을 다시 쓰려는 경우 주의**하세요.
> 로블록스 개인서버 링크 자체는 살아 있으니, 필요하면 새 알림을 이용하면 됩니다.
>
> ℹ️ 유출 추적에 쓰이는 **워터마크와 감시 코드는 지우지 않습니다.** 몇 달 뒤

### 🧱 모듈 분리 원칙

`verify.py` · `link_guard.py` · `verify_db.py`는 **포인트 이코노미와 완전히 독립**되어 있습니다.

- `utils/database.py`(포인트 · 상점 · 뽑기 · 제보 · 블랙리스트)를 **전혀 import 하지 않습니다**.
- 포인트를 지급 · 차감하지 않고, `/로그`의 활동 기록에도 남기지 않습니다.
- MongoDB 컬렉션(`verify_settings`, `linkguard_settings`, `protected_links`,
  `link_clicks`, `link_watermarks`, `guarded_keys`, `roblox_links`)과
  로컬 JSON 파일(`data/verify_settings.json` 등)을 **별도로 사용**합니다.

따라서 이코노미 쪽 코드를 수정하거나 제거해도 인증 · 링크 보호는 그대로 동작합니다.

## 🚀 환경 변수 설정 (`.env`)

```env
# ── 필수 ─────────────────────────────────────────────
DISCORD_TOKEN=디스코드 봇 토큰
MONGO_URI=몽고DB 연결 문자열

# ── 중계 링크 신원 게이트 (relay_links 를 켤 때 필요) ──
DISCORD_CLIENT_ID=디스코드 애플리케이션 ID
DISCORD_CLIENT_SECRET=디스코드 OAuth 시크릿
SECRET_KEY=쿠키 서명용 임의 문자열 (직접 생성)

# ── 로블록스 계정 연동 (선택) ─────────────────────────
ROBLOX_CLIENT_ID=로블록스 OAuth 클라이언트 ID
ROBLOX_CLIENT_SECRET=로블록스 OAuth 시크릿

# ── 중계 주소 (Oracle 에서는 반드시 필요) ──
#    없으면 링크 중계가 조용히 꺼지고,
#    버튼에 로블록스 주소가 그대로 박혀 우클릭 한 번에 샙니다.
PUBLIC_BASE_URL=https://krbiomehunt.duckdns.org
```

**리다이렉트 URI** — 각 개발자 포털에 아래를 **정확히** 등록해야 합니다.

| 서비스 | 등록할 주소 |
| :--- | :--- |
| 디스코드 | `https://<서비스>/auth/callback` |
| 로블록스 | `https://<서비스>/roblox/callback` |

| 없으면 생기는 일 | 증상 |
| :--- | :--- |
| `MONGO_URI` | 죽지 않고 `data/*.json` 으로 **조용히** 폴백. 재시작마다 포인트 소실 |
| `DISCORD_CLIENT_ID/SECRET` | 신원 게이트가 **자동으로 꺼진 채** 동작 (링크는 나감) |
| `SECRET_KEY` | 신원 확인 쿠키를 서명할 수 없어 게이트 비활성 |
| `ROBLOX_CLIENT_ID/SECRET` | `/로블록스연동` 이 "준비되지 않았습니다" 로 응답 |

> ⚠️ `MONGO_URI` 누락은 **정상 동작처럼 보입니다.** Render 파일시스템은 휘발성이라
> 재시작마다 포인트가 사라지는데도 봇은 멀쩡히 돌아갑니다.
> 기동 로그의 `Point storage:` 줄로 **반드시** 확인하세요.

> 🛡️ 봇 DB 계정에는 `readWrite` 만 주세요. `atlasAdmin` 이면 `MONGO_URI` 가 새는 순간
> 전 데이터가 삭제될 수 있습니다.
